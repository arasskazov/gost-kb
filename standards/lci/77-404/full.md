#  Введение

Стандарты серии «Система поддержки жизненного цикла изделия» (группа 3 - «Информационные модели изделия» и группа 4 - «Программные средства поддержки ЖЦ») содержат комплекс требований к представлению данных об изделии, направленных на обеспечение интероперабельности программных средств и возможности обмена данными об изделии при решении практических задач на стадиях и этапах жизненного цикла изделия.

Требования к информационным моделям, регламентирующим состав и способ структуризации данных об изделии (общие данные об изделии, геометрия и топология, структура изделия, сведения о материалах и др.) приведены в стандартах группы 3.

Настоящий стандарт устанавливает общие требования к способу представления данных об изделии в виде обменного файла, с учетом того, что требования к составу данных и способу их структуризации с необходимой степенью подробности уже установлены в стандартах группы 3 с использованием языка описания данных Express. Представление данных об изделии в виде обменного файла рассматривается как один из способов обеспечения интероперабельности по ГОСТ Р 77.402.

В стандарте приведены возможные технологии представления данных: текстовое представление STEP по ГОСТ Р 10303-21, текстовое представление в виде файла JSON.

В формате справочного приложения А приведены сведения о возможности представлении данных в виде размеченного текста XML.

Основное назначение настоящего стандарта – установить требования к преобразованию конструкций языка описания данных EXPRESS по ГОСТ Р 10303-11 в текстовое описание экземпляров информационных объектов в нотациях STEP, JSON и XML , соответственно.

В перспективе, с учетом опыта реализации и применения представленных технологий в составе отечественных программных средств, предполагается разработать детализированные методические рекомендации по использованию указанных методов.

4.  Основные положения

4.1 В соответствии с ГОСТ Р 77.403 интероперабельность программных средств СПЖЦ изделия может реализовываться с использованием обменного файла, требования к которому изложены в настоящем стандарте.

4.2 Обменный файл – файл, содержащий данные об изделии в виде ИМ изделия, соответствующей требованиям, которые регламентированы стандартами ГОСТ Р 77.302 – ГОСТ Р 77.306 (и другими стандартами группы 3).

4.3 Обменный файл выполняется в виде размеченного текст определенного формата, установленного в профиле интероперабельности:

\- STEP (раздел 5);

\- STEP-JSON (раздел 6);

\- XML, сформированного согласно спецификации \[2\] и приложению А.

5.  Представление данных об изделии в виде обменного файла формата STEP

5.1 Текстовый обменный файл STEP должен соответствовать требованиям ГОСТ Р ИСО 10303-21, а также дополнительным требованиям, приведенным в настоящем разделе.

5.2 Обменный файл в формате STEP должен включать следующие секции:

\- заголовочная секция (header section) – обязательная, неповторяющаяся секция, содержит сведения об обменном файле. Начало секции обозначается ключевым словом HEADER; конец секции- ENDSEC;

Примечание – Заголовочная секция может включать в себя экземпляры следующих объектов: file_description, file_name, и file_schema (должны включаться именно в таком порядке). Дополнительно могут использоваться объекты schema_population, file_population, section_language и section_context.

\- секция привязки (anchor section) – обязательная, неповторяющаяся секция, определяет имена объектов для внешних ссылок (из других обменных файлов). Начало секции обозначается ключевым словом ANCHOR, конец секции- ENDSEC;

\- секция ссылок (reference section) - необязательная, неповторяющаяся секция, содержит ссылки на экземпляры объектов в секции данных обменного файла. Начало секции обозначается ключевым словом REFERENCE, конец секции- ENDSEC;

\- секция данных (data section) - необязательная, повторяющаяся секция, содержит информацию об изделии. Начало секции обозначается ключевым словом DATA, конец секции- ENDSEC;

\- секция подписи (signature section) - необязательная, повторяющаяся секция, содержит информацию об источнике данных (автор или отправитель файла) и подтверждает достоверность передаваемых данных. Начало секции обозначается ключевым словом SIGNATURE, конец секции- ENDSEC.

Если секция подписи включена в обменный файл, то она должна быть расположена после секций с данными непосредственно перед лексемой «END-ISO-10303-21».

5.3 Обменный файл может включать в себя несколько секций подписи. Каждая секция должна начинаться с ключевого слова SIGNATURE и заканчиваться ключевым словом ENDSEC.

При использовании электронной подписи следует руководствоваться требованиями ГОСТ Р 2.051.

Примечания – При формировании массива подписываемых данных необходимо учитывать только символы, определенные в ГОСТ Р ИСО 10303-21.

5.4 Первая и последняя строки текстового обменного файла должны иметь вид, соответственно:

«ISO-10303-21;

…..:

END-ISO-10303-21;»

5.5 В секцию данных включаются экземпляры ИО, составляющие ИМ изделия, сведения о котором передаются в обменном файле.

5.6 В Приложении Б приведен пример обменного файла в формате STEP.

6.  Представление данных в виде текстового обменного файла STEP-JSON

6.1 Обменный файл в формате STEP-JSON должен соответствовать требованиям стандарта \[1\], а также дополнительным требованиям, приведенным в настоящем разделе.

6.2 Обменный файл в формате STEP-JSON должен включать следующие секции:

\- секцию заголовка – обязательная, неповторяющаяся секция, содержит сведения об обменном файле;

\- секцию данных – необязательная, неповторяющаяся секция, содержит информацию об изделии, начинается с ключевого слова instances;

\- секцию подписи – необязательная, повторяющаяся секция, содержит информацию об источнике данных (автор или отправитель файла) и подтверждает достоверность передаваемых данных.

6.3 Секция заголовка должна содержать следующие ключевые слова (лексемы):

\- «FORMAT» (в соответствии с настоящим стандартом имеет значение «STEP-JSON 1.0»);

\- «SCHEMA» (в соответствии с настоящим стандартом может принимать значения «GOST R 77.XXX»).

По аналогии с ГОСТ Р ИСО 10303-21, в секции заголовка могут быть представлены дополнительные сведения об обменном файле:

\- time_stamp;

\- author;

\- organization;

\- originating_system и др.

6.4 В секции данных содержится массив объектов JSON, в которых представлены экземпляры ИО, составляющие ИМ изделия и определенные в ГОСТ Р 77.002–77.006, записанные с учетом синтаксиса языка разметки JSON по стандарту \[1\].

6.5 Каждый экземпляр ИО из схемы данных (SCHEMA) описывается одним объектом JSON, имеющим следующие атрибуты:

\- «id» – числовой идентификатор экземпляра ИО внутри файла, предназначенный для создания ссылок на этот экземпляр. Формат идентификатора установлен в ГОСТ Р ИСО 10303-21 (символ «#» и целочисленный номер, например, «#345»);

\- «type» – строка, содержащая тип ИО из схемы данных, указанной по ключевому слову SCHEMA (например, «product», «document» и др.). Для комплексных ИО тип ИО должен формироваться из нескольких имен объектов, соединенных символом «+». Например, **«*next_assembly_usage_occurrence*** + ***quantified_assembly_component_usage***» или «***serial_numbered_effectivity*** + ***product_definition_effectivity***».

\- «attributes» – список атрибутов ИО (согласно схеме данных) и их значения, заданные для конкретного экземпляра ИО. Имя атрибута указывается в параметре «attribute_name<sub>n</sub>», значение - в параметре «value».

6.6 Значения атрибутов в зависимости от типа данных, указанного в схеме данных, различных типов задаются следующим образом:

\- STRING –строка;

\- INTEGER –целое число;

\- REAL –вещественное число;

\- LOGICAL – задается в формате, установленном в ГОСТ Р ИСО 10303-21 (символы приведенные к верхнему регистру с точками в начале и конце: «.F.» для FALSE, «.T.» для TRUE и «.U.» для UNKNOWN);

\- INSTANCE – задается как строка с указанием идентификатора экземпляра ИО (атрибут «id»);

\- ENUMERATION – задается в формате, установленном в  
ГОСТ Р ИСО 10303-21 (символы приведенные к верхнему регистру с точками в начале и конце, например, «.MADE.», «.BOUGHT.», «.NOT_KNOWN.», «.ASSEMBLY.», «.PART.», «.MATERIAL.», «.KIT.» и «.СOMPLEX.»);

\- ARRAY, LIST, SET – задаются как списки согласно правилам , установленным в \[1\] (в квадратных скобках перечень значений через запятую).

Приложение А  
(справочное)  
Представление данных в виде текстового обменного файла XML

А1. Технология представления данных об изделии в формате XML изложена в стандарте \[3\] (к моменту разработки настоящего стандарта еще не переведен на русский язык и не выпущен в виде ГОСТ Р ИСО).

Указанный стандарт определяет правила преобразования схем ISO 10303 в вид XSD-схем, согласно документу \[4\], а также требования к представлению экземпляров информационных объектов, определенных в указанных выше схемах, в формате XML.

А2. Преобразование ИМ из формата EXPRESS в формат XSD может осуществляться несколькими способами:

\- простое преобразование, в результате которого на основе EXPRESS-схем формируются базовые XSD схемы (default schema), полностью соответствующие исходным;

\- сложное преобразование, в результате которого на основе EXPRESS-схем и конфигурационных файлов формируются так называемые производные XSD-схемы (derived schema).

Примечание — Конфигурационный файл представляет собой файл, содержащий правила конфигурирования (модификации) базовой схемы.

А3. Стандарт \[3\] предусматривает несколько видов XML-документов, отличающихся специальным признаком.

а) XML документ типа «**iso-10303-28»** может содержать:

\- схемы данных;

\- конфигурационные файлы (для настройки схем данных);

\- собственно данные.

б) XML документ типа «uos» может содержать только данные (набор экземпляров ИО), структурированных в соответствии с одной конкретной базовой схемой данных (default XML schema).

Примечание — В стандарте ISO 10303-28 используется термин ***uos*** - «unit of serialization», что можно перевести как «контейнер», «модуль данных» или «пакет данных» - информационная единица в которых размещена информация об изделии.
